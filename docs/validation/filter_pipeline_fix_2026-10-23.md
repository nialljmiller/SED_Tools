# Filter-pipeline follow-up — 2026-10-23

This follows the [live audit](filter_pipeline_audit_2026-10-23.md). The filter API and CLI now refuse undeclared partial downloads, retry transient NJM failures, and describe partially available optical-path components accurately. The MESA colors source in `/Users/njm/MESA/mesa` was rebuilt to read SED_Tools metadata and apply each filter's energy or photon detector convention.

## Cirrus and public mirror

The live files are served by Apache from `/media/data3/MESA/SED_Tools/data` through the `/sed_tools` alias. The public index and sampled filter URLs returned HTTP 200 during this follow-up; Apache was active. Its `mod_evasive.conf` sets a 500-request/5-second site threshold and a 60-second block that returns HTTP 403. Apache access and error logs are root-only and `sudo -n` requires a password, so the precise cause of the earlier 403s remains unconfirmed. Repeated requests later returned 200, consistent with a temporary block. The client now retries transient 403, 429 and 5xx responses with bounded delays and honors numeric `Retry-After` up to 60 seconds.

The downloader no longer writes a MESA index from whatever files happened to arrive. A cached published set now requires a manifest declaring its expected bands; when NJM has an index but no manifest, the downloader creates one using that authoritative index. The SVO downloader already records expected bands in a manifest. A fresh `Filters.fetch('HST', 'WFPC2-WF')` downloaded all 52 published curves and 81 component files, with zero missing manifest paths and a complete index.

Two previously identified published roots were curated on Cirrus, with exact raw copies and SHA-256 provenance in `/media/data3/MESA/SED_Tools/source_evidence/filters/2026-10-23/manifest.json`:

| Served curve | Minimal change | Public check |
| --- | --- | --- |
| `CAHA/PANIC/Y.dat` | Average four SVO responses at 10230.1 Å into one sample | 1,583 rows, strictly increasing wavelength, nonnegative response |
| `Gemini/GSAOI/Klong_cont.dat` | Set the sole negative edge response at 23464 Å from `-3.4e-05` to zero | 665 rows, strictly increasing wavelength, nonnegative response |

The original-source component curves remain intact. Public GET requests for both curated files returned 200 and were parsed independently.

## MESA integration

`colors_utils.load_filter` now skips comment metadata and the CSV header, counts only numerical samples, reads `DetectorType`, and rejects malformed or physically invalid curves with a nonzero MESA exit. A missing `DetectorType` retains the legacy photon convention. Synthetic flux and Vega/AB/ST zero points use the same selected weighting. A MESA unit test reads a tagged energy-counting CSV and checks that its energy-weighted magnitude differs from photon weighting. `make check` passes after rebuilding `colors`; on this Mac the linked checker needed a local SDK rpath correction to find `libcrmath.dylib`.

The isolated `custom_colors` test executable was rebuilt against this source. Runs with the unmodified tagged Liverpool/IOO set and a tagged energy-counting GSAOI product finished without photometry errors and produced finite magnitudes. A run with an uncurated GSAOI published root failed with exit code 1 and named its invalid file. Logs are under `/Users/njm/.cache/SED_Tools/filter_pipeline_audit_20261023/` (`mesa_ioo_fixed.log`, `mesa_gsaoi_energy_fixed.log`, `mesa_gsaoi_invalid_raw.log`).

## Remaining data review

The initial 637-curve audit encountered only the two curves above. A subsequent full scan of **all 3,963 published root curves on Cirrus** found 107 with numerical anomalies before those repairs and **105 remaining afterward**. Of those 105, 30 contain at least one non-increasing wavelength step and 75 contain negative transmission samples; none had nonfinite or unparseable rows. The complete per-file list is [`filter_curve_issues_2026-10-23.csv`](filter_curve_issues_2026-10-23.csv), generated by `scripts/audit_filter_curves.py`. Some anomalies are substantial (for example, a minimum transmission of `-0.0943` in `Gemini/AcqCam_S/I.dat`), so they were left unchanged pending source-by-source review. MESA now rejects these curves clearly if selected. NJM still serves their source values; acquisition currently verifies completeness, not numerical validity.
